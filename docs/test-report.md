# 系统测试报告骨架

## 1. 文档定位
- 用途：作为最终提交包中的测试记录文档，统一收纳功能测试、性能测试、兼容性测试、问题记录和结果分析。
- 当前阶段：本文件只定义测试报告结构、取数来源和待填项，不预填任何未执行的测试结果。
- 最终提交边界：`纳入最终提交包`。

## 2. 主来源与依赖

| 主题 | 主来源 | 本文档的使用方式 |
| --- | --- | --- |
| 测试要求口径 | `docs/superpowers/specs/2026-06-26-mental-health-system-design.md` | 锁定至少要覆盖的测试类型 |
| 自动化测试文件 | `tests/`、`pytest.ini` | 最终回填已执行的用例与结果 |
| 业务行为范围 | `app/`、`templates/`、`static/` | 确认功能测试点 |
| 数据与部署前提 | `docs/deployment-guide.md`、`sql/` | 说明测试前置条件 |
| 报告图表素材 | `docs/assets/README.md` | 关联截图与测试表格 |

## 3. 老师要求锁定
- 报告中必须包含 `系统测试`、`测试任务`、`测试目标`、`测试方案`、`测试结果及分析`。
- 测试结果至少要覆盖 `系统功能测试` 与 `系统性能测试`。
- 设计说明已明确兼容性测试至少应关注 `Chrome`、`Edge`、`Safari` 的说明口径；如条件受限，必须真实注明限制。
- 最终文件夹命名必须为 `班级-姓名-学号`。
- 截止时间为 `第 18 周周三（2026 年 7 月 1 日 24:00 前）`。

## 4. 最终成稿应包含的结构

### 4.1 测试任务
- 本次测试覆盖哪些系统端口和功能模块。
- 测试由谁执行、在什么环境执行。

### 4.2 测试目标
- 证明核心功能可用。
- 证明部署后的基本可运行性。
- 记录性能与兼容性表现。
- 发现已知限制与残留问题。

### 4.3 测试环境
- 硬件环境。
- 操作系统。
- Python / MySQL / 浏览器版本。
- 测试数据准备方式。

### 4.4 测试方案
- 功能测试方法。
- 自动化测试命令。
- 手工验证步骤。
- 性能测试口径。
- 兼容性测试口径。

### 4.5 功能测试结果
- 学生端功能。
- 后台功能。
- 大屏展示。
- 异常流程与边界条件。

### 4.6 性能测试结果
- 首页加载。
- 测评页加载。
- 大屏页加载。
- 数据量与网络条件说明。

### 4.7 兼容性测试结果
- Chrome。
- Edge。
- Safari 或替代说明。
- 手机端响应式表现。

### 4.8 缺陷与结论
- 已修复问题。
- 未修复但已知限制。
- 是否满足课程提交最低要求。
