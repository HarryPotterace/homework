# 项目交付文档总控

## 1. 文档定位
- 这是当前工作树中交付文档的唯一导航入口。
- 目标：统一说明每份文档的用途、结构、主来源、待填内容、最终提交边界和当前状态。
- 当前阶段：服务于“编码前准备”和交付范围控制，不把草稿、占位文件或设计预期误写成最终结果。
- 最终提交边界：`不纳入最终提交包`，属于内部过程文档。

## 2. 老师要求总览
- 交付内容必须覆盖：`Word 版课程报告`、`完整工程源码`、`系统配置/部署说明书`、`数据库 SQL 文件`。
- 报告必须包含：封面、目录、参考文献、系统流程图、ER 图、测试结果、界面截图。
- 最终文件夹命名：`班级-姓名-学号`。
- 截止时间：`第 18 周周三（2026 年 7 月 1 日 24:00 前）`。
- 格式要求已锁定到 `docs/course-report-outline.md`：`A4` 纵向、中文 `宋体 5 号`、英文 `Times New Roman`、`1.5 倍行距`、标题按老师模板。

## 3. 文档分类

### 3.1 外部输入材料
- 老师提供材料，只作为需求来源保留在仓库中，不纳入最终提交包。
- 包括：
  - `2025-2026学年第2学期《人机交互技术及应用》课程大作业.doc`
  - `2025-2026学年第2学期《人机交互技术及应用》大作业评分标准.doc`
  - `期末考试说明.pptx`

### 3.2 内部过程文档
- 用于需求审计、设计控制、实施准备和交付范围管理。
- 默认保留在仓库中，但不放入给老师的最终提交包。

### 3.3 最终交付文档
- 直接服务于最终提交或最终课程报告整理。
- 在编码完成前先建立可执行骨架，在真实实现后回填内容。

## 4. 使用规则
- 新增任何文档，先在这里登记。
- 同一主题只能有一个主来源文档，其它文档只做引用、摘要或回链。
- 状态描述必须区分三类：
  - `已锁定骨架`
  - `待真实实现回填`
  - `已定稿`
- 任何文档都不得把“预期要做的事情”写成“已经做完的结果”。

## 6. 最终提交包边界

### 6.1 应纳入最终提交包
- 源码与运行文件：`app/`、`templates/`、`static/`、`run.py`、`requirements.txt`
- 测试文件：`tests/`、`pytest.ini`
- 最终交付文档：`docs/deployment-guide.md`、`docs/database-design.md`、`docs/test-report.md`、`docs/course-report-outline.md`、`docs/assets/README.md`
- SQL 文件：`sql/schema.sql`、`sql/seed.sql`、`sql/README.md`
- 最终 Word 报告：按老师模板整理后的正式文档

### 6.2 不纳入最终提交包
- `.git/`、缓存目录、解释器缓存文件
- 老师提供的原始要求材料
- 内部过程文档：`docs/superpowers/`、`docs/requirements-audit.md`、`docs/document-control.md`

## 7. 更新顺序
1. 需求或范围变化：先改设计说明，再改要求审计和报告提纲。
2. 表结构变化：先改 `sql/`，再改数据库说明和部署说明。
3. 页面或交互变化：先改实现与素材，再改课程报告提纲相关章节说明。
4. 测试结果变化：先改测试报告，再同步到课程报告正文。
5. 最终打包前：统一检查目录命名 `班级-姓名-学号` 与截至 `2026-07-01 24:00` 的提交要求。

## 8. 当前阶段完成判定
- 当前完成标准：每份关键文档都已写清用途、主来源、待填项和提交边界。
- 当前未完成项：真实部署内容、真实 SQL、真实测试结果、真实截图和正式 Word 报告正文仍待后续回填。
