# 智慧校园心理辅导与情绪感知交互子系统设计说明

## 1. 设计目标
- 面向课程题目《智慧校园心理辅导与情绪感知交互子系统设计与实现》，构建一个 `B/S` 结构系统。
- 同时支撑 `手机端学生界面`、`PC 端咨询师/管理员后台`、`大屏端学院心理态势脱敏数据看板`。
- 符合作业说明、评分标准和提交要求，保证 `源码 + 报告 + 部署说明 + SQL` 能组成完整交付。

## 2. 要求审计结论
根据 `期末考试说明.pptx`、`课程大作业.doc`、`大作业评分标准.doc`，项目必须覆盖以下内容：

### 2.1 必做功能
- 学生注册与登录。
- 个人信息查看与修改。
- 心理测评，至少支持 `PHQ-9` 和 `GAD-7` 两类量表。
- 情绪感知与自适应交互。
- 心理咨询预约。
- 移动端响应式适配。
- PC 后台数据查看与处理。
- 大屏脱敏可视化展示。

### 2.2 明确不能遗漏的实现点
- 注册和登录前端必须有 `JavaScript` 非空校验。
- 注册前端必须有密码强度校验。
- 后端必须校验学号唯一性。
- 登录必须使用 `Session` 管理状态。
- 情绪感知至少要采集 `mousemove`、`click`、`keydown` 三类行为。
- 预约排班应支持异步获取或异步校验时段，不能只停留在纯静态展示。
- 大屏只能展示脱敏聚合结果，不能暴露个人身份信息。

### 2.3 交付文档要求
- `Word 版课程报告`。
- `完整工程源码`。
- `系统配置/部署说明书`。
- `数据库 SQL 文件`。
- 报告中必须包含封面、目录、参考文献、系统流程图、ER 图、测试结果、界面截图。
- 最终提交文件夹命名方式为 `班级-姓名-学号`。
- 截止时间为 `第 18 周周三（7 月 1 日 24:00 前）`。

### 2.4 评分标准直接约束
- 报告必须体现人机交互技术相关理论与应用，不只展示功能页面。
- 报告必须写清研究背景、研究现状、方法与创新、结果分析和课程心得。
- 报告内容必须和最终实现保持一致，不能写入未实现内容。
- 需要补充参考文献，以及量表来源、情绪规则依据等方法支撑。

## 3. 方案比较

### 方案 A：Flask 单体应用
- 后端、模板、静态资源放在一个工程。
- 优点是实现快、部署简单、适合课程作业闭环。
- 缺点是前端交互不如前后端分离灵活。

### 方案 B：前后端分离
- 后端提供 API，前端单独工程实现。
- 优点是结构现代。
- 缺点是工程复杂度、部署说明和联调成本明显更高。

### 方案 C：只做页面演示型项目
- 优点是界面完成快。
- 缺点是无法满足评分标准里“能够编程处理、展示结果、分析结果”的要求。

### 结论
- 采用 `方案 A`。
- 技术栈固定为 `Flask + Jinja2 + Bootstrap + 自定义 CSS/JS + MySQL`。
- 情绪算法采用 `行为规则 + 文本关键词情绪分析` 的轻量方案，保证可实现、可测试、可写入报告。

### 4.3 大屏端脱敏看板

## 5. 系统架构设计

### 5.1 总体架构
- 表现层：Jinja2 模板 + Bootstrap + 自定义 CSS/JS。
- 控制层：Flask 路由按学生端、后台、大屏、API 拆分。
- 业务层：认证、测评、情绪分析、预约、统计服务。
- 数据层：MySQL 持久化业务数据，SQLite 仅用于测试或本地快速运行。

### 5.2 路由边界
- 学生端：`/`、`/register`、`/login`、`/profile`、`/assessment`、`/vent`、`/emotion`、`/appointments`
- 后台：`/admin/login`、`/admin/dashboard`、`/admin/assessments`、`/admin/vents`、`/admin/appointments`
- 大屏：`/screen`
- AJAX/API：`/api/behavior`、`/api/screen-data`、`/api/schedules`

### 5.3 模块职责
- 认证模块：注册、登录、退出、Session 校验。
- 测评模块：量表展示、选项提交、分数计算、结果建议。
- 树洞模块：匿名内容提交、情绪标签生成、后台查看。
- 情绪模块：行为采集、文本关键词分析、界面模式切换。
- 预约模块：排班展示、预约创建、时段可用性校验、取消与后台处理。
- 看板模块：脱敏聚合统计、图表数据生成。

## 6. 人机交互设计

补充主来源：
- 学生端首页、后台总览页、大屏看板页的联动改版细则，以 `docs/superpowers/specs/2026-06-26-page-optimization-design.md` 为主来源。
- 本文只保留总体交互原则，不重复细化三页模块级方案。

### 6.1 交互目标
- 降低学生使用心理服务的心理压力。
- 页面语言保持温和、去标签化。
- 优先保证手机端操作便捷。
- 将“先表达、再测评、后预约”设计成自然路径。

### 6.2 学生端交互原则
- 按钮与表单控件在移动端不小于 `44px`。
- 首页突出 `心理测评`、`匿名树洞`、`预约咨询` 三个主入口。
- 情绪感知页根据行为状态切换主题色、留白和提示文案。
- 树洞模块默认匿名，不向学生侧暴露身份关联。

### 6.3 后台交互原则
- 突出信息密度和处理效率。
- 咨询师优先看个体记录和预约。
- 管理员优先看整体统计和趋势。

### 6.4 大屏交互原则
- 全屏展示。
- 大字号、高对比度。
- 以聚合指标和趋势展示为主。

## 7. 情绪感知算法设计

### 7.1 行为特征
- 鼠标移动速度。
- 点击频率。
- 输入停顿次数。

### 7.2 文本特征
- 焦虑关键词。
- 低落关键词。
- 高风险关键词。

### 7.3 推断规则
- 鼠标速度过快或点击频率过高，优先推断为 `焦虑`。
- 输入停顿频繁且文本存在低落词汇，优先推断为 `低落`。
- 文本出现高风险关键词，如“撑不下去”“伤害自己”等，标记为 `需关注`。
- 情绪结果映射为界面模式：`default`、`gentle`、`calm-down`。

### 7.4 结果用途
- 学生端自适应界面提示。
- 树洞内容后台分级查看。
- 大屏按聚合维度统计趋势。

### 7.5 算法依据与文献要求
- 报告中必须明确说明：本项目采用 `交互行为规则推断 + 文本关键词情绪分析` 的轻量算法方案。
- 参考文献至少覆盖：
  - 人机交互设计相关理论。
  - 心理测评量表来源。
  - 文本情绪分析或情绪计算相关研究。
- 参考文献最终写入课程报告和 `docs/course-report-outline.md` 对应位置。

## 9. 文档管理设计
这里的“文档管理”定义为 `项目交付文档管理`，不是系统内新增业务模块。

### 9.1 管理目标
- 用一个总控文档统一管理全部交付文档。
- 明确每份文档“解决什么问题、包含什么内容、依赖哪些文档、由什么实现结果驱动更新”。
- 在需求、设计、实现、测试持续变化时，保证文档之间不互相打架。

### 9.2 文档总控机制
- 新增一份 `docs/document-control.md` 作为交付文档总入口。
- 这份文档必须逐项登记每份文档的：
  - 文档名称。
  - 目标用途。
  - 必含内容。
  - 上游依据。
  - 下游影响。
  - 当前状态。
  - 最后更新时间。
- 当需求、设计、数据库、接口、测试结果发生变化时，先更新对应文档，再回写总控文档中的状态与影响范围。

### 9.3 文档清单
- `document-control.md`：总控文档，说明所有交付文档的用途、内容边界和状态。
- 需求与设计说明：说明题目要求、系统边界、交互设计、算法设计、数据库设计。
- 实施计划：说明实现顺序、测试策略、文件结构和落地步骤。
- 部署说明书：说明环境、依赖、数据库导入、配置与启动方式。
- 数据库说明书：说明表结构、字段含义、ER 图、约束关系。
- 测试记录文档：说明测试任务、测试目标、测试方案、测试结果与分析。
- 课程报告正文草稿：对应老师模板中的正式报告内容。
- 截图与图表素材清单：管理首页、测评页、树洞页、后台页、大屏页、流程图、ER 图等素材。

### 9.4 管理规则
- 所有交付文档统一放在 `docs/`。
- SQL 文件统一放在 `sql/`。
- 报告配图和素材统一放在 `docs/assets/`。
- `document-control.md` 是唯一的文档导航入口，后续新增文档必须先登记。
- 报告内容与代码实现保持一致，避免报告和系统不一致。
- 如果同一信息出现在多份文档中，必须明确“哪份是主来源”，其余文档只做引用或摘要。

### 9.5 主来源约定
- 需求、范围、边界：以 `设计说明` 为主来源。
- 实现顺序、任务拆分、测试执行顺序：以 `实施计划` 为主来源。
- 建表语句、初始化数据：以 `sql/schema.sql` 与 `sql/seed.sql` 为主来源。
- 部署步骤：以 `部署说明书` 为主来源。
- 报告章节内容：以 `课程报告正文草稿` 为主来源。
- 交付检查状态：以 `document-control.md` 为主来源。

## 10. 测试与验收设计

### 10.1 功能验收
- 学生可注册、登录、修改信息。
- 学生可完成测评并生成结果。
- 学生可发布匿名树洞并生成情绪标签。
- 学生可预约、查看、取消预约。
- 后台可查看记录并处理预约。
- 大屏可显示脱敏统计。

### 10.2 交互验收
- 学生端在手机宽度下可正常使用。
- 情绪状态变化时页面样式有可见反馈。
- 树洞匿名逻辑在学生端成立。

### 10.3 性能与兼容性口径
- 性能测试至少记录：
  - 首页首次加载时间。
  - 测评页首次加载时间。
  - 大屏页首次加载时间。
- 兼容性测试至少覆盖：
  - `Chrome`
  - `Edge`
  - `Safari`
- 若本地无法完整覆盖 `Safari`，需在测试记录中注明限制条件。

### 10.4 文档验收
- 报告章节完整。
- 图表编号和标题完整。
- 有 ER 图、流程图、测试表格、系统截图。
- 有类谱系树及其说明。
- 总控文档中每份文档都已登记用途、内容和状态。
- 文档之间没有相互矛盾的模块说明、字段定义或交付描述。

### 10.5 报告格式验收
- 封面按老师模板填写。
- 正文汉字为宋体 5 号。
- 英文为 Times New Roman。
- 行距为 1.5 倍。
- 标题格式符合模板要求。
- A4 纵向版式。
