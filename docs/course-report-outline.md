# 课程报告正文提纲

## 1. 格式要求
- 封面按老师模板填写。
- 正文汉字使用宋体 5 号。
- 英文使用 Times New Roman。
- 正文行距为 1.5 倍行距。
- 标题格式按老师模板执行。
- A4 纵向排版。
- 标题层级示例：`一概述`、`1.1 标题2`、`1.1.1 标题3`、`1）标题4`。
- 报告内容必须与最终代码实现一致，不能写入未实现功能。

## 2. 章节结构

### 第一章 系统需求分析
- 1.1 系统需求
  - 研究背景与意义。
  - 高校心理健康管理现状与痛点。
- 1.2 功能需求
  - 三端用户场景与功能边界。
- 1.3 性能需求
  - 响应速度、兼容性、可用性与脱敏要求。

### 第二章 可行性分析
- 2.1 技术可行性
  - Flask 单体方案与其它方案对比。
- 2.2 操作可行性
  - 学生端、后台端、大屏端的使用门槛与维护成本。
- 2.3 可行性分析结论

### 第三章 概要设计
- 3.1 系统设计原则
  - 亲和、低打扰、去标签化、脱敏展示。
- 3.2 系统设计目标
- 3.3 系统总体架构
- 3.4 设计流程图
- 补充：类谱系树及其说明

### 第四章 系统详细设计与实现
- 4.1 功能模块设计与实现
- 4.1.1 用户注册模块
- 4.1.2 用户登录模块
- 4.1.3 心理测评功能模块
- 4.1.4 情绪感知与自适应交互模块
  - 必写：行为规则、关键词规则、界面自适应策略。
- 4.1.5 心理咨询预约功能模块
- 4.1.6 移动端响应式适配模块
- 4.1.x 方法与创新点
  - 说明本系统如何把人机交互理论、情绪感知规则和三端适配组合成可落地方案。
- 4.2 数据库设计与实现
- 4.2.1 系统 E-R 模型
- 4.2.2 数据库设计
- 4.3 系统开发环境
- 4.3.1 硬件环境
- 4.3.2 软件环境

### 第五章 系统测试
- 5.1 系统测试
- 5.1.1 测试任务
- 5.1.2 测试目标
- 5.1.3 测试方案
- 5.2 测试结果及分析
- 5.2.1 系统功能测试
- 5.2.2 系统性能测试
- 5.2.3 兼容性测试
- 5.2.4 结果分析与评价

### 第六章 总结与展望
- 心得体会要求真实，不浮夸。
- 回顾设计取舍、系统不足与可扩展方向。

### 参考文献
- 需补充课程相关理论、人机交互设计原则、量表来源、情绪规则依据等文献。

## 3. 必补内容
- 研究背景与意义。
- 研究现状。
- 方法与创新点。
- 结果分析与评价。
- 文件夹命名规则：`班级-姓名-学号`。
- 提交截止时间：`第 18 周周三（7 月 1 日 24:00 前）`。
- 截图、流程图、ER 图、类谱系树、测试表格。
- 正式提交物必须包含：`Word 报告`、`完整源码工程`、`系统配置说明书`、`数据库 SQL 文件`。
