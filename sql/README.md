# SQL 目录说明

## 1. 文档定位
- 用途：说明 `sql/` 目录中每个文件的职责、执行顺序、主来源和当前状态。
- 当前阶段：只锁定目录边界和回填规则，不宣称 SQL 已经定稿。
- 最终提交边界：`纳入最终提交包`，作为 SQL 文件的配套说明。

## 2. 目录内容

| 文件 | 用途 | 当前状态 | 主来源 |
| --- | --- | --- | --- |
| `schema.sql` | 正式建表脚本 | 占位文件存在，待定稿 | 最终数据库设计 |
| `seed.sql` | 初始化数据脚本 | 占位文件存在，待定稿 | 最终演示数据方案 |

## 3. 执行顺序
1. 先执行 `schema.sql`。
2. 再执行 `seed.sql`。
3. 真实命令、数据库名和导入截图，后续回填到 `docs/deployment-guide.md`。

## 4. 与其他文档的边界
- `sql/` 目录负责可执行脚本本身。
- `docs/database-design.md` 负责解释表结构与 ER 图。
- `docs/deployment-guide.md` 负责解释如何导入这些脚本。

## 5. 老师要求落点
- `数据库 SQL 文件` 是明确要求的最终交付物。
- 最终提交包根目录命名必须为 `班级-姓名-学号`。
- 截止时间：`第 18 周周三（2026 年 7 月 1 日 24:00 前）`。

## 6. 当前阶段完成判定
- 当前完成标准：SQL 目录职责、文件清单、执行顺序和文档边界明确。
- 最终完成标准：两个脚本均定稿，且与数据库说明、部署说明、课程报告完全一致。
